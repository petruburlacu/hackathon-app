# Contributing

Thanks for helping out! Anyone at Opus 2 is welcome to contribute.

## Getting access

- **Regular contributors:** ask the maintainer ([@petruburlacu](https://github.com/petruburlacu)) to add your GitHub account as a collaborator. Then push branches directly to this repo.
- **Drive-by fixes:** fork the repo, push to your fork, and open a PR against `master`.

## Workflow

1. Get the app running locally with the [Quick start](./README.md#quick-start). A local Convex backend ("Start without an account") is enough for most changes.
2. Branch off `master`, using `<type>/<short-description>`, e.g. `feat/team-chat` or `fix/leaderboard-ties`.
   Types: `feat`, `fix`, `chore`, `refactor`, `test`, `docs`.
3. Commit with [Conventional Commits](https://www.conventionalcommits.org/): `feat(teams): add team chat`. Keep each commit to one logical change.
4. Before pushing, run:
   ```sh
   npm run typecheck
   npm run lint
   npm run build
   ```
5. Open a PR against `master`. Say what changed and why, and how you tested it. Keep PRs small, with one concern per PR.

## Working with Convex

- `convex/schema.ts` is the database schema. `npx convex dev` (part of `npm run dev`) pushes schema and function changes to your dev deployment as you save.
- `convex/_generated/` is generated by `convex dev`. Commit it, but never edit it by hand.
- Schema changes must be compatible with data already in production. Adding optional fields is safe. Renaming or removing fields, or making them required, needs a migration. Raise it in the PR.
- Every public `query`/`mutation` is callable by any client. Check `getAuthUserId(ctx)`, and `isAdmin(ctx, userId)` for admin-only actions, inside the function.
- Users' usernames live in the Convex Auth `authUsername` component. Use `getUsername()` from `convex/users.ts`.

## Deployments

Merges to `master` deploy to production on Vercel, which also deploys `convex/` to the production Convex deployment. If your change needs a new environment variable, document it in the README's *Configuration* table and tell the maintainer before merging.
